# SFT from Scratch — Qwen3-4B

A minimal, from-scratch **Supervised Fine-Tuning (SFT)** pipeline for `Qwen/Qwen3-4B`,
covering data loading, single-/multi-GPU training (Accelerate + DeepSpeed ZeRO),
and benchmark evaluation on **math** (GSM8K) and **coding** (LeetCodeDataset).

## Repository layout

```
sft_from_stratch/
├── main.py                       # training entry point (argparse)
├── model/                        # Qwen3 model loading + reference src
├── data_utils/                   # datasets (LeetCode, OpenR1-Math) + mixed dataloader
├── trainer/sft_trainer.py        # custom SFT training loop
├── eval/                         # evaluation scripts
│   ├── eval_gsm8k_math500.py     # GSM8K / MATH-500 accuracy
│   ├── eval_leetcode.py          # LeetCode pass@k
│   └── gen_cot_full.py           # generate CoT traces for LeetCode (teacher: claude-sonnet-4-6)
├── train_singlenode_singlegpu.sh # single-GPU training (SLURM)
├── train_singlenode_multigpu.sh  # 4-GPU training (Accelerate + DeepSpeed)
├── train_openr1math.sh           # math SFT on OpenR1-Math-220k
├── ds_config.json                # DeepSpeed config
└── outputs/
    ├── checkpoint/               # trained checkpoints (math / coding)
    └── eval/                     # evaluation results (this README's source)
```

## Results

All evaluations compare the **base** `Qwen/Qwen3-4B` against checkpoints produced by this
pipeline. Results are read from `outputs/eval/`.

### Math — GSM8K (exact-match accuracy)

Full GSM8K test set (1319 problems), `max_new_tokens = 2048`.

| Model | Accuracy | Correct / Total |
|-------|:--------:|:---------------:|
| Qwen3-4B (base) | 81.73% | 1078 / 1319 |
| **Qwen3-4B + SFT** (OpenR1-Math, 5k subset) | **90.07%** | 1188 / 1319 |

SFT on a 5k subset of `OpenR1-Math-220k` improves GSM8K accuracy by **+8.3 points**.

### Coding — LeetCodeDataset (pass@k)

`n_samples = 5`, sampling-based `pass@1` / `pass@5`, `max_new_tokens = 9192`.

| Model | pass@1 | pass@5 |
|-------|:------:|:------:|
| Qwen3-4B (base) | 24.82% | 33.77% |
| Qwen3-4B + SFT (LeetCode, solution-only) | 22.11% | 30.26% |
| **Qwen3-4B + SFT (LeetCode, CoT distilled)** | 24.47% | **35.96%** |

Notes:
- Naïve SFT on raw (solution-only) LeetCode answers **hurts** performance — the base model
  is already strong on this distribution and short answers degrade its reasoning.
- Adding distilled **Chain-of-Thought** traces (generated by `claude-sonnet-4-6` in
  `eval/gen_cot_full.py`, which prepends a `<think>…</think>` block to the ground-truth
  solution) recovers pass@1 and lifts **pass@5 to 35.96%** (best, +2.2 over base).


## Training

### Single GPU
```bash
sbatch train_singlenode_singlegpu.sh
```

### Multi-GPU (4× GPU, Accelerate + DeepSpeed ZeRO)
```bash
sbatch train_singlenode_multigpu.sh   # coding (LeetCode)
sbatch train_openr1math.sh            # math (OpenR1-Math-220k)
```

Key hyperparameters (see `main.py` for the full list):

| Arg | Default / used | Notes |
|-----|----------------|-------|
| `--model_path` | `Qwen/Qwen3-4B` | base model |
| `--dataset` | `leetcode` / `openr1math` | task selection |
| `--lr` | `1e-6` | learning rate |
| `--batch_size` | `1` | per-device |
| `--gradient_accumulation_steps` | `32` | effective batch ≈ 32 × num_gpus |
| `--max_seq_len` | `4096` | training context |
| `--epochs` | `1` | single epoch |

## Evaluation

```bash
sbatch eval/eval_gsm8k_math500.sh     # GSM8K / MATH-500
sbatch eval/eval_leetcode.sh          # LeetCode pass@k
```

Each run writes `eval_results.json` (summary metrics + per-task `details`) and
`raw_outputs.jsonl` (raw generations) under `outputs/eval/<benchmark>/<model>/`.

## Takeaways

- **Math SFT works cleanly**: even a small 5k math-reasoning subset yields a large,
  reliable GSM8K gain (+8.3 pts).
- **Data quality > data presence for coding**: SFT only helps when the targets contain
  reasoning. CoT-distilled targets beat both the base model and solution-only SFT on pass@5.
